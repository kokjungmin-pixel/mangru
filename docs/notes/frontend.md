## sec_get — SEC 요청 공용 함수 (2026-11-15)
- 무엇을 하는가: 모든 SEC 주소를 이 함수 하나로 받아 JSON 또는 원본 bytes로 돌려준다. 404나 끝내 실패하면 예외 없이 `None`.
- 어떻게 하는가: User-Agent `Mangru-Team <SEC_CONTACT_EMAIL>`, 요청 사이 0.2초, 3번 시도(1초·2초 대기), 받은 원본은 `data_cache/raw/http/` 에 저장해 같은 주소는 다시 요청하지 않는다.
- 한계: 저장본이 있으면 새로 받지 않으므로, 바뀌는 주소(공시 목록 등)를 갱신하려면 저장본을 지워야 한다.

## 13F 정보표 읽기·정리 — parse_infotable, clean_rows (2026-11-15)
- 무엇을 하는가: 13F 정보표 XML을 종목별 행으로 읽고, 옵션·원금 행을 빼고 같은 CUSIP을 합친다.
- 어떻게 하는가: 태그 앞의 네임스페이스를 `{*}` 경로로 무시하고 읽으며, 정리 규칙은 Frontend 문서 B3-5를 따른다.
- 한계: 2023-01-03 이전 제출본의 금액 단위 변환(×1000)과 정정본 처리는 아직 없다.

## 데모 운용사 후보 정리 — scripts/collect_candidates.py (2026-11-15)
- 무엇을 하는가: 후보 운용사마다 13F 연속 분기 수, 종목 수, 예탁증서 비중, CRD, SEC 등록일을 SEC에서 받아 B2 조건표로 낸다.
- 어떻게 하는가: EDGAR submissions API, 최신 13F 정보표, IAPD 회사 상세 API를 `sec_get` 으로 부른다. 이 표로 Akre·Brown Capital·Warburg Pincus를 골랐다.
- 한계: 예탁증서 비중은 titleOfClass 글자로 추정한 값이고, 단일 전략 여부와 CIO 교체 보도는 사람이 따로 확인해야 한다.
