## 나를 막는 의존 관계

```
PM 키 전달(11/13) ──→ Backend 모델 선택 ──→ Backend 토론
Frontend 데모 3곳(11/15) ──→ PM DEMO_MANAGERS ──→ 전원 실데이터 개발
Frontend sec_client(11/17) ──→ Data enrich_cusips(11/18) ──→ Frontend 수집 도구(11/19~)
Data 신호(11/28) ──→ Backend 토론 실제 입력 ──→ PM E2E v0(11/29)
Frontend 변화 비교(12/1) ──→ Data ADV 신호 ──→ PM E2E v1(12/6)
```

## PR 받을 때마다 볼 것

- [ ] 자기 파트 폴더만 수정했는가 (`state.py`·`config.py` 는 PM만)
- [ ] 함수 결과가 `validate(결과, 타입)` 을 통과하고 `pytest` 전체가 통과하는가
- [ ] 키·개인정보가 코드·커밋·로그에 없는가
- [ ] 외부 주소·열 이름·모델 ID를 썼다면 `docs/verified.md` 에 적었는가
- [ ] README "지금 상태" 표에서 그 함수를 `가짜` → `✅` 로 바꿨는가

## 참고

- 각 파트 C장 2단계("mock 먼저 올리기")는 PM 뼈대 커밋에 **이미 들어 있다.** 팀원은 자기 파일의 mock 자리를 실제 구현으로 바꾸면 된다고 공지한다.
- 막혔을 때 줄이는 순서 (A10): Should 두 개 → RAG → ADV 2A는 Item 2·8만 → 업종·규모 기준값을 임시값으로. 수집·토론·리포트·화면은 줄이지 않는다.
